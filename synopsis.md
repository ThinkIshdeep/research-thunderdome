# Synopsis — Research Thunderdome

**Ishdeep Singh · 12 November 2026**

## V2 interface release

A guarded experiment pipeline.

- Arrange and inspect data, split, preprocessing and model nodes
- Run real allowlisted model-training campaigns
- Rank completed validation trials and pin two configurations to compare
- Inspect rejected protocol fixtures and the final held-out test

Pipeline dragging changes layout only. Trials execute the declared fixed protocol. The underlying domain scope and research-extension boundaries below remain explicit.

## Implemented release

Runnable source: `lab/automl.py`. Interface and backend are included. Tests and benchmark outputs accompany this distribution.

## Limits of the implemented release

Allowlisted sklearn configurations with budgeted random search. No arbitrary code execution or self-certified scientific discovery.

## Original specification and proposed extensions

The material below preserves the design ambitions. Future-tense features and anticipated challenges are not completed-development claims.

Research Thunderdome

**Tagline:** The experiment claims a breakthrough. First, it has to survive the audit.

### Concept, problem, and users

Research Thunderdome manages small ML experiment campaigns that must defend their conclusions with recorded evidence. Automated search can produce impressive results while overlooking leakage, inconsistent comparisons, or repeated tuning against the same validation set.

Target users are students and ML teams working with bounded tabular tasks. The research question is whether budget-aware experiment planning finds useful models more efficiently than random search without increasing invalid-experiment rates.

### Proposed product and workflow

Users register a dataset, define the prediction task, lock the split, choose permitted model families, and assign a compute budget. The platform proposes trials, validates configurations, runs jobs, and produces reports linked to actual logs. It must distinguish a hypothesis from an observed result and an observed result from an established conclusion.

Screens: dataset profile, campaign editor, job queue, trial comparison, ablation builder, audit findings, and report. The report includes failed runs, cancelled jobs, resource use, and uncertainty. Optional language-model narration may summarize structured run records; it cannot create metrics or silently change the task.

### Data and system design

Records: `DatasetVersion`, `SplitManifest`, `ExperimentSpec`, `Trial`, `Artifact`, `Metric`, `AuditFinding`, and `ReportClaim`. Every claim links to run IDs. Each trial records source revision, environment lock, parameters, hardware, duration, seed, and termination reason.

Use a few permitted tabular datasets with distinct characteristics, rather than one handpicked success case. Keep final test data inaccessible to the search worker. For cross-dataset meta-learning, hold out entire datasets, not just rows within familiar datasets.

### Algorithms and experiments

Baseline: a fixed preprocessing/model pipeline and budget-matched random search. Advanced search can use Optuna's sampling and pruning facilities [R6]. Pruning decisions use intermediate validation measurements; final reporting must still state how many configurations received full training.

Initially execute allowlisted estimator configurations rather than arbitrary generated code. Enforce CPU, memory, time, file-access, and network limits at the job runtime. Containers need explicit restrictions; merely running a container does not establish isolation. An LLM can propose a structured trial specification, which a validator accepts or rejects.

Evaluate final held-out score, best validation score as a function of compute, total compute used, invalid-trial detection, and reproduction success. Introduce known-invalid experiments as audit fixtures. Ablate planning heuristics and pruning while preserving budgets. Nested evaluation or a held-out dataset family can test whether repeated search has overfit the benchmark selection process.

### Anticipated problems, in my voice

| What could go wrong | My likely reaction | Engineering response |
|---|---|---|
| A large gain comes from leakage | “The model has solved the exam by finding the answer sheet.” | Locked splits, pipeline audits, and test-set separation |
| Search improves the validation set but little else | “We have developed a very expensive validation-set enthusiast.” | Untouched final tests and cross-dataset evaluation |
| A summary invents an experiment outcome | “The report has started conducting research independently of the computer.” | Generate claims only from structured, traceable records |

### Demo, milestones, and limits

Run several fair trials, inject a deliberately invalid preprocessing case, show its rejection, and reproduce a valid winner from the recorded configuration. Milestones: job runner; baseline campaign; lineage; audits; budgeted search; reproducibility study. Deliver an auditable experimentation assistant. Automatic scientific discovery and self-certified research conclusions are outside the release claim.




## Problems actually encountered during the makeover

| The problem | In my voice | What changed |
|---|---|---|
| Sample B overwrote the file used by sample A | “Bro, this is an A/B test, why did B steal A’s identity?” | Recordings now get unique file names; a regression test checks both files remain distinct and unchanged. |
| A duplicate highlight followed row positions instead of duplicate evidence | “Apparently every third row had been arrested on vibes.” | Duplicate highlights now use exact record content and jump to a real duplicate. |
| The table displayed a rounded number that search did not match | “I copied the number from your own screen, my guy.” | Search checks both raw values and the formatted values visible in the table. |
| Graph labels became tiny on a phone | “Causal inference, now available to ants.” | Graph workspaces keep readable node widths and scroll within their own viewport. |
| Robot movement and the play button disagreed about whether it was running | “Gordon left the parking spot while the button was still contemplating life.” | The live flag is synchronized after accepted commands and remains off after rejected commands. |
| Fast screenshots caught an interface between renders | “The UI took a smoke break precisely when the camera arrived.” | Captures were inspected, incomplete frames replaced, and videos labelled as edited screenshots. |

These are observed build issues. Proposed research challenges in the original specifications remain proposed; this log does not invent months of model training or real deployments.
